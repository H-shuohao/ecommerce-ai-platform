# 多模态素材中心：真实文件接入

## 本次解决的问题

早期素材中心只保存 `uri`、商品编号、标签和来源等元数据，相当于“登记了一本素材目录”，但文件本身并没有进入平台。

现在增加了真实文件接入闭环：

```text
浏览器上传文件
  ↓
校验 Content-Type、文件签名和大小
  ↓
分块读取并计算 SHA-256
  ↓
相同内容复用已有文件
  ↓
data/assets 持久化文件
  ↓
SQLite 保存文件元数据和商品关系
  ↓
素材检索 / 下载 / 内容 Agent 审核后沉淀
```

## 接口

- `POST /api/v1/assets/upload`：通过 multipart/form-data 上传图片、视频或文本。
- `GET /api/v1/assets/{asset_id}`：查询文件元数据。
- `GET /api/v1/assets/{asset_id}/content`：下载本地文件。
- `GET /api/v1/assets`：按商品、素材类型和标签检索。

当前允许的文件类型：

- 图片：JPEG、PNG、WebP；
- 视频：MP4、WebM；
- 文本：TXT、Markdown、JSON。

默认单文件上限为 50 MB，可使用 `ASSET_MAX_UPLOAD_MB` 调整。存储目录可使用 `ASSET_STORAGE_DIR` 配置；Docker 默认通过现有 `data` 挂载目录持久化。

## 去重与安全

系统不会直接使用用户文件名作为磁盘路径，而是边读取边计算 SHA-256，并用“哈希值 + 受控扩展名”保存。例如：

```text
local-asset://fa9c...2be.png
```

这样可以：

- 避免 `../` 等路径穿越；
- 相同文件只保存一份，降低重复占用；
- 用哈希校验文件内容；
- 保留原始文件名用于下载展示。

图片和视频还会检查文件头签名，避免只修改扩展名或 Content-Type 就把任意文件伪装成媒体文件。超出限制返回 HTTP 413，类型或签名不匹配返回 HTTP 400。

## 当前边界

当前是单机本地持久化方案，适合个人作品集、内部工具和单节点部署。它不是云对象存储：

- 暂无 MinIO、S3 或火山 TOS 适配；
- 暂无分片上传、断点续传和 CDN；
- SHA-256 去重目前按整个素材记录复用，同一文件尚未建立多商品关联表。

下一阶段可以抽象统一的 Storage Adapter，把本地实现替换为 MinIO/TOS，而上层素材检索、内容审核和 Agent 工具接口无需重写。

## 面试表达

> 素材中心最初只有元数据登记，我后来补齐了真实文件上传链路。上传时分块读取，限制文件大小，通过 MIME 和文件签名做双重校验，再计算 SHA-256 进行内容寻址和去重。文件保存在 Docker 持久化目录，SQLite 保存原文件名、类型、大小、哈希和商品关联，并提供受控下载接口。当前明确定位为单机方案，如果进入多实例环境，会通过 Storage Adapter 迁移到 MinIO 或 TOS。
